1. INTRODUCTION                                  *simplewhichkey-introduction*

SimpleWhichKey shows what may follow a prefix key.  Pause after <C-w> and a
panel lists every window command; pause after the leader, "g", "z", "[", "]",
'"' or "`" and the same happens.  Keep typing at your usual speed and the panel
never appears.

Three sources feed one panel:

    Vim's built-in commands   <C-w>v, gU, zt and friends are not mappings, so
                              they cannot be discovered; the plugin carries
                              description tables for them.
    Your mappings             found with |maplist()| every time the panel
                              opens, including buffer-local ones, with a
                              description derived from the right hand side
                              when you have not written one.
    The live editor state     the registers that hold something and the marks
                              that are set, listed under '"', "'" and "`".

==============================================================================
2. REQUIREMENTS                                  *simplewhichkey-requirements*

Vim 9.1 or newer, compiled with |+popupwin|, |+textprop| and |+timers|.
No external program, no daemon, no other plugin.

==============================================================================
3. HOW IT WORKS                                     *simplewhichkey-mechanics*

    1. Normal/Visual prefixes enter Start() through <Cmd>. Operator prefixes
       use a recursive <expr> hook that leaves Vim's pending operator live.
    2. The selector waits |g:simplewhichkey_delay| milliseconds.  If the next
       key arrives while waiting, no panel is drawn.
    3. Otherwise the panel opens and keys are read with |getcharstr()| until
       the sequence stops being a prefix.
    4. Normal/Visual sequences are replayed with |feedkeys()|. An operator
       motion is returned directly from its expression mapping. Hooks are
       suspended for both paths and restored once Vim is idle.

Because step 4 replays the keys instead of interpreting them, mappings keep
their own semantics: <expr>, <ScriptCmd>, <Plug>, recursive, buffer-local,
|:map-silent|, counts and registers all behave as they would without the
plugin. Operator selection never cancels or reconstructs the pending state,
so |g@| callbacks and 'unnamed'/'unnamedplus' mirroring remain native.

When other mappings extend a prefix, Vim itself waits 'timeoutlen' before
dispatching it, so the panel opens without further delay.  A shorter
'timeoutlen' (400ms is comfortable) therefore makes the leader panel feel
faster.

4. USING THE PANEL                                      *simplewhichkey-panel*

    a listed key        choose it; a group opens the next level
    an unlisted key     replayed as typed, so the panel never blocks a key
    <BS>                back one level and restore its previous page
    <PageUp>/<PageDown> previous/next overflow page; an explicit mapping wins
    mouse wheel         previous/next page when this level overflows
    <Esc>, CTRL-C       close the panel and run nothing

Entries whose description starts with "+" are groups: more keys follow.
When the grid cannot fit every entry, its title shows [page/total PgUp/PgDn].
Use those keys or the mouse wheel to visit every page.  An explicit PageUp or
PageDown mapping at the current level takes precedence over paging, so it is
never hidden; the keyboard fallback also works in terminal Vim with 'mouse'
disabled. Page position is remembered separately for every visited level
during the current key sequence, so entering a group and pressing <BS> returns
to the same parent page.

TEXT OBJECTS                                       *simplewhichkey-textobjects*

Text objects exist only in Visual and Operator-pending mode, which is also why
they are the most forgotten part of Vim's grammar: pressing "d" cannot show
them and nothing in the editor can enumerate them.  "i" and "a" are therefore
hooked in both modes by default, so pausing in "di", "ca" or "va" lists every
|text-objects| entry -- word, WORD, sentence, paragraph, the bracket, brace,
angle, paren and tag blocks, and the three quoted forms -- with the
interchangeable keys ("i(", "i)", "ib") all shown, because the point is to
reach the one you remember.

Operator-pending "i"/"a" go through the same |<expr>| hook as "g": the pending
operator, its multiplied count and its register stay live, so "d2i(" keeps its
count and "." repeats what you chose.  Visual "i"/"a" go through the |<Cmd>|
hook and keep the live selection.

Any |:omap| or |:xmap| under "i" or "a" is discovered the usual way, so plugin
text objects such as vim-matchup's "i%" appear next to the built-in ones.

"i" and "a" are hot keys.  If the panel gets in the way, either give them a
shorter wait through |g:simplewhichkey_delay| >
    let g:simplewhichkey_delay = {'default': 200, 'i': 80, 'a': 80}
<
or drop them from |g:simplewhichkey_prefixes| altogether.

5. OPTIONS                                            *simplewhichkey-options*

                                                 *g:simplewhichkey_prefixes*
Which prefixes open a panel, per mode.  Only "n", "x" and "o" are used. >
    let g:simplewhichkey_prefixes = {
          \ 'n': ['<leader>', '<localleader>', 'g', 'z', 'Z', '<C-w>',
          \       '[', ']', '"', "'", '`'],
          \ 'x': ['<leader>', '<localleader>', 'g', 'z', '[', ']',
          \       '"', "'", '`', 'i', 'a'],
          \ 'o': ['g', '[', ']', 'i', 'a'],
          \ }
<
A prefix that is already mapped by you is left alone.

"i" and "a" are the text object introducers and appear in the "x" and "o"
lists only; in Normal mode they start Insert.  See
|simplewhichkey-textobjects|.

                                                    *g:simplewhichkey_enable*
Set to 0 to keep the plugin loaded but out of the way.  Default 1.

                                                     *g:simplewhichkey_delay*
Milliseconds to wait before drawing the panel, for prefixes Vim dispatches
immediately.  Default 200.

It may also be a dictionary, so prefixes that need different waits can have
them.  Keys are prefix notation, optionally scoped to a mode with "n:", "x:"
or "o:", plus "default" for everything not named: >
    let g:simplewhichkey_delay = {
          \ 'default': 200,
          \ '<leader>': 0,
          \ 'i': 80,
          \ 'a': 80,
          \ 'o:g': 250,
          \ }
<
Lookup order is "mode:prefix", then "prefix", then "default".  Prefix keys are
compared after termcode expansion, so "<leader>", "<Space>" and a literal " "
name the same prefix.  |:SimpleWhichKeyHealth| prints the delay every hooked
prefix resolves to.

A prefix that other mappings extend has already cost a full 'timeoutlen'
before the hook runs, so 0 suits the leader; a prefix Vim dispatches instantly
needs a real pause.

                                                  *g:simplewhichkey_position*
"bottom" (default), "top" or "center".

                                                 *g:simplewhichkey_separator*
Text between key and description.  Default " -> " (an arrow).

                                                *g:simplewhichkey_max_height*
Maximum panel height in lines.  0 (default) means half the screen.

                                            *g:simplewhichkey_max_desc_width*
Longest description before it is shortened.  Default 30.  Descriptions shrink
further when the panel would otherwise not fit.

                                                      *g:simplewhichkey_sort*
"key" (default) or "group" to list groups first.

                                                    *g:simplewhichkey_border*
Draw a border around the panel.  Default 1.

                                             *g:simplewhichkey_show_builtins*
List Vim's own commands under <C-w>, g, z, [ and ].  Default 1.

                                             *g:simplewhichkey_hide_aliases*
Hide a built-in Ctrl variant when a plain key with the same meaning is already
listed, for example <C-w><C-v> next to <C-w>v.  Default 1.

                                                    *g:simplewhichkey_ignore*
Key sequences to leave out of the panel.  They keep working; they are only
hidden. >
    let g:simplewhichkey_ignore = ['<leader>1', '<leader>2']
<
==============================================================================
6. DESCRIPTIONS                                  *simplewhichkey-descriptions*

Descriptions are optional.  A mapping to <Cmd>SimpleGitDiff<CR> is listed as
"SimpleGitDiff" and a mapping to <Plug>(simpletree-toggle) as
"simpletree-toggle".

The flat form names sequences directly; a description starting with "+" names
a group: >
    call simplewhichkey#Describe({
          \ '<leader>f':  '+file',
          \ '<leader>ff': 'find files',
          \ })
<
The nested form matches the dictionary vim-which-key used, so an existing
g:which_key_map can be reused unchanged: >
    call simplewhichkey#Register('<leader>', 'g:which_key_map', 'n')
<
Both accept a mode as the last argument, "n" by default.

7. COMMANDS                                          *simplewhichkey-commands*

                                                              *:SimpleWhichKey*
:SimpleWhichKey [prefix]    Open the panel for [prefix], default the leader.

                                                        *:SimpleWhichKeyVisual*
:SimpleWhichKeyVisual [prefix]
                            The same, listing visual mode mappings.

                                                      *:SimpleWhichKeyOperator*
:SimpleWhichKeyOperator [prefix]
                            The same, listing operator-pending mappings and
                            built-in motions; [prefix] defaults to "g".  The
                            default operator prefixes are "g", "[", "]", "i"
                            and "a".  Counts, named registers and Vim's
                            default-register behavior survive replay.

                                                       *:SimpleWhichKeyRefresh*
:SimpleWhichKeyRefresh      Take the configured prefixes again.  Needed after
                            changing 'mapleader' or |g:simplewhichkey_prefixes|
                            at runtime.

                                *:SimpleWhichKeyToggle* *:SimpleWhichKeyEnable*
                                                      *:SimpleWhichKeyDisable*
:SimpleWhichKeyToggle       Hints on/off.

                                                        *:SimpleWhichKeyHealth*
:SimpleWhichKeyHealth       Report the state of every hooked prefix: whether
                            the hook is in place or taken by another mapping,
                            and how many mappings and built-ins it lists.

8. FUNCTIONS                                        *simplewhichkey-functions*

simplewhichkey#Keys({mode}, {prefix})                  *simplewhichkey#Keys()*
        What the panel would list for {prefix}, as a dictionary of key to
        {desc, group, source}.  The quickest way to check a configuration: >
            :echo simplewhichkey#Keys('n', '<C-w>')
<
simplewhichkey#Describe({dict} [, {mode}])         *simplewhichkey#Describe()*
simplewhichkey#Register({prefix}, {spec} [, {mode}])
                                                   *simplewhichkey#Register()*
simplewhichkey#Forget()                              *simplewhichkey#Forget()*
        See |simplewhichkey-descriptions|.  Forget() drops every registered
        description.

simplewhichkey#Start({prefix} [, {mode}])             *simplewhichkey#Start()*
        Open the panel for {prefix}.  This is what the hooks call.

10. LIMITS                                             *simplewhichkey-limits*

- Insert and command-line mode are not hooked.
- A prefix already mapped by the user is not taken over.
- |:normal| without "!" in a script goes through the replay, so those keys run
  after the :normal command finishes rather than inside it.  Script code should
  use :normal! anyway.
- Operator-pending hints default to "g", "[", "]", "i" and "a". An exact user
  |:omap| on a prefix keeps ownership; remove the "o" entry from
  |g:simplewhichkey_prefixes| to turn the default hooks off.
- The operator keys themselves ("d", "c", "y") are not hooked: hinting them
  would mean listing every motion after the most-used key in Vim.
